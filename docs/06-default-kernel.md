# Step 6 — Booting linux-surface by default

```sh
./install.sh --step 5
# or directly:
bash scripts/05-default-kernel.sh
bash scripts/05-default-kernel.sh --undo
```

## The problem this solves

After [step 3](03-kernel.md) you have two kernels, and the boot menu still
selects your distribution kernel when the countdown runs out. Which means:
every single time you start the machine, you must catch the menu, press an
arrow key, and pick `linux-surface` — or you end up without a touchscreen and
wonder why.

That is the right default while the new kernel is unproven. It stops being
the right default once it is.

## Do not edit `default_entry`

The obvious move is to open `/boot/limine.conf` and change:

```
default_entry: 2
```

**Do not.** That file is regenerated by `limine-entry-tool` every time a
kernel package is installed, upgraded or removed. Your edit disappears — not
with an error, just silently, and you find out months later when a routine
update quietly puts you back on the old kernel.

Worse, `default_entry` is a positional index. Install a third kernel and the
number means something different.

## What to do instead

Change `BOOT_ORDER`, which is *configuration* rather than generated output,
through a drop-in file:

```sh
# /etc/limine-entry-tool.d/zz-surface-first.conf
BOOT_ORDER="linux-surface, linux-t2, linux-omarchy, linux-omarchy-*, *, *fallback, Snapshots"
```

`limine-entry-tool` reads `/etc/limine-entry-tool.d/*.conf` in alphabetical
order, so a `zz-` prefix wins against Omarchy's own `omarchy-defaults.conf`.
The tool then places `linux-surface` first by itself, and `default_entry`
follows along because it is regenerated at the same time.

Then, and this is the part people miss:

```sh
sudo limine-update
```

Without it the new order only takes effect after the *next* kernel update —
which is a confusing way to discover that it did not work. The same note
appears in the review of [Omarchy PR
#7857](https://github.com/omacom/omarchy/pull/7857).

`scripts/05-default-kernel.sh` does all of this, and builds the new order from
your existing one rather than from a hard-coded string, so your distribution
kernel keeps its place directly below.

## Verify before rebooting

The script prints the resulting menu. Check three things:

1. Is `//linux-surface` listed **first**?
2. Is your distribution kernel still listed, right after it?
3. Does every `cmdline` still carry `cryptdevice=` and `rootflags=subvol=`?
   The script counts them for you — the two numbers must match.

Point 3 is the one that would leave you unable to unlock your own disk.

## When to do it

Not immediately. The working document this repository grew out of puts it
well: switch the default only after the kernel has booted cleanly *several*
times. Two boots is the bare minimum reading of that.

Give it a few days of ordinary use — suspend, detach, dock, a reboot or two —
and switch once nothing has surprised you.

This is why step 5 is excluded from `./install.sh --all`. A script cannot
judge whether your kernel has earned your trust yet.

## If it goes wrong

Nothing here is dangerous. Your old kernel is still in the menu, one arrow key
away, and the snapshots are below it.

```sh
bash scripts/05-default-kernel.sh --undo
```

removes the drop-in and regenerates the menu.

## The countdown

The menu waits a few seconds before booting the default. To change that, set a
timeout in `/boot/limine.conf`:

```
timeout: 10
```

Be aware that `limine-entry-tool` may rewrite that file. If the setting does
not survive, it is not worth fighting: pressing any arrow key stops the
countdown for as long as you like.
